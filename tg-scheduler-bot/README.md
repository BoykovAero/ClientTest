# tg-scheduler-bot — комплект для развёртывания

Инфраструктура для бота-планировщика: каждый день в 08:45 (Europe/Moscow) бот
спрашивает в Telegram, как пройдёт день, принимает ответ текстом или голосом
(Whisper), разбирает его через GPT и пишет события одновременно в **Google
Calendar** и в **iCloud** (он же «Календарь» на Mac).

## Команды бота

| Команда | Что делает |
| --- | --- |
| `/start` | проверка связи |
| `/plan` | задать вопрос про план прямо сейчас, не дожидаясь 08:45 |
| `/today` | что записано на сегодня, с возможностью удалить |
| `/models` | проверить, какие модели отвечают твоему ключу |

### Удаление

`/today` показывает события пронумерованными и рядом — кнопки с номерами.
Нажатие открывает подтверждение, и только после него событие удаляется
**сразу из обоих календарей**.

Пара в iCloud находится по UID, который бот записал при создании. У событий,
заведённых не ботом, такого UID нет — они удалятся только из Google, о чём
бот прямо скажет.

Обычное сообщение — текстом или голосом — бот разбирает как план дня.

## Как записывать время

| Что написал | Как понял |
| --- | --- |
| `1555-1620 установить клод` | диапазон: 15:55–16:20 |
| `1800 сколково` | голое время — это **конец**; начало берётся от конца предыдущего дела |
| `в 18:00 созвон` | предлог — значит **начало**; длительность по умолчанию |
| `в 18:00 созвон на час` | начало и явная длительность |

Список, где каждая строка начинается со времени, разбирается **без модели** —
регулярным выражением. Правило жёсткое, обращаться за ним к модели незачем:
она подставляет начало там, где названо только окончание, и цепочка ломается.
Всё остальное по-прежнему разбирает модель.

Так список дел подряд ложится в день сплошной лентой, без наложений и
пропусков:

```
1555-1620 установить клод     ->  15:55–16:20
1800 сколково                 ->  16:20–18:00
1930 физ шк                   ->  18:00–19:30
2045 книга                    ->  19:30–20:45
```

Файл с расписанием (`.docx`, `.xlsx`, `.csv`, `.txt` или скриншот) он тоже
примет: разберёт, покажет список найденного и дождётся подтверждения, прежде
чем что-то записывать.

К файлу стоит добавить подпись — что именно взять: «расписание 11Е инж на
понедельник». Большое расписание целиком модель не осилит, а с подписью
выберет нужную часть.

## Два пути развёртывания

**Без компьютера** — всё в браузере и Telegram, хостинг собирает контейнер из
GitHub, секреты живут в его панели. Доступ к Google — через сервисный аккаунт,
поэтому браузер на своей машине не нужен и токен не протухает через 7 дней.
См. [CLOUD.md](CLOUD.md).

**На своём сервере** — Oracle/Hetzner, systemd, установка по ssh.
См. [DEPLOY.md](DEPLOY.md). С чего начать:

```bash
python3 setup_env.py
```

Скрипт спросит каждый ключ, сразу проверит его обращением к настоящему сервису
и запишет `.env` с правами 600. Где брать значения — [DEPLOY.md](DEPLOY.md),
шаги 1–4: токен у @BotFather, ключ OpenAI, app-specific password Apple,
OAuth Google.

## Секреты

`.env`, `credentials.json`, `token.json` в git **не попадают** — они
перечислены в `.gitignore`. Перед пушем:

```bash
git status --short     # этих файлов быть не должно
```
