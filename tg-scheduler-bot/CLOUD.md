# Развёртывание без своего компьютера

Обычный путь (`DEPLOY.md`) требует терминала: OAuth Google открывает браузер
локально, деплой идёт по ssh. Этот документ описывает путь, где **терминал не
нужен ни разу** — всё делается в браузере и в Telegram на телефоне.

Разница ровно в двух местах:

| | DEPLOY.md | этот путь |
| --- | --- | --- |
| Доступ к Google | OAuth-токен, нужен браузер на своей машине + `google_auth_setup.py` | сервисный аккаунт: скачал JSON в браузере — и всё |
| Хостинг | свой сервер, установка по ssh | хостинг, который собирает контейнер прямо из GitHub |
| Секреты | файлы `.env`, `token.json` на диске сервера | переменные окружения в панели хостинга |
| Срок жизни доступа | в статусе Testing протухает за 7 дней | не истекает |

---

# Шаг 1. Telegram

С телефона, в приложении Telegram:

1. [@BotFather](https://t.me/BotFather) → `/newbot` → название → username,
   оканчивающийся на `bot`. В ответ придёт `TELEGRAM_BOT_TOKEN`.
2. [@userinfobot](https://t.me/userinfobot) → `/start`. Число из поля `Id` —
   это `ALLOWED_USER_ID`.
3. Открой своего нового бота и нажми `/start`. Без этого бот не сможет
   написать тебе первым.

# Шаг 2. Распознавание речи и разбор текста

Боту нужны две вещи: перевести голосовое в текст и разобрать текст в список
дел. Обе умеет любой сервис с API, совместимым с OpenAI. Вариантов два.

## Вариант A — Groq: бесплатно, без карты

1. [console.groq.com](https://console.groq.com/) → регистрация (карта не нужна).
2. **API Keys** → **Create API Key** → имя `tg-scheduler-bot` → скопируй
   ключ вида `gsk_...`, он показывается один раз.
3. Переменные:

```
OPENAI_API_KEY=gsk_...
OPENAI_BASE_URL=https://api.groq.com/openai/v1
OPENAI_MODEL=qwen/qwen3.8-27b
OPENAI_TRANSCRIBE_MODEL=whisper-large-v3
OPENAI_VISION_MODEL=qwen/qwen3.8-27b
```

`qwen/qwen3.8-27b` умеет и разбирать текст, и читать картинки, поэтому
годится сразу для двух переменных.

Бесплатный тариф Groq на момент написания — порядка 30 запросов в минуту и
тысячи в сутки, ограничение на загрузку 25 МБ. Нагрузка этого бота — единицы
запросов в день, то есть с огромным запасом. Лимиты меняются, сверь на сайте.

> **Имена моделей в этом документе — ориентир, а не истина.** Провайдеры
> снимают модели с обслуживания каждые несколько месяцев и меняют номера
> версий. Не угадывай: отправь боту любое сообщение, и на неизвестной
> модели он сам перечислит в ответе те, что доступны твоему ключу —
> останется вписать подходящую в переменную.
>
> Список может содержать и модели, закрытые тарифом: такие отвечают `403`,
> и бот это отдельно называет, чтобы не искать опечатку в имени.
>
> Чтобы не перебирать имена по одному, отправь боту **`/models`** — он
> проверит каждую модель настоящим запросом и покажет, какие отвечают и
> какие из них принимают картинки.
>
> Если ни одна доступная модель не читает картинки — ничего страшного:
> расписания из `.xlsx` и `.docx` бот разбирает сам, без моделей, и делает
> это точнее распознавания скриншота. Google Таблицу можно выгрузить
> через **Файл → Скачать → Microsoft Excel (.xlsx)**.

## Вариант B — OpenAI: платно

[platform.openai.com](https://platform.openai.com/) → **Settings → Billing**,
пополни баланс (подписка ChatGPT Plus доступа к API не даёт) → **API keys →
Create new secret key**.

```
OPENAI_API_KEY=sk-...
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_MODEL=gpt-4o-mini
OPENAI_TRANSCRIBE_MODEL=whisper-1
```

> Переключиться между вариантами можно в любой момент: меняются четыре
> переменные, код трогать не нужно.

# Шаг 3. iCloud

[appleid.apple.com](https://appleid.apple.com/) → **Sign-In and Security →
App-Specific Passwords** → **+** → название `tg-scheduler-bot`.

Пароль вида `abcd-efgh-ijkl-mnop` — это `ICLOUD_APP_PASSWORD`,
а почта Apple ID — `ICLOUD_APPLE_ID`.

# Шаг 4. Google — через сервисный аккаунт

Здесь и исчезает нужда в браузере на **своей** машине: сервисный аккаунт
действует от своего имени, экран согласия ему не нужен.

## 4.1. Проект и API

1. [console.cloud.google.com](https://console.cloud.google.com/) → селектор
   проектов → **New Project** → имя `tg-scheduler-bot` → **Create**.
   Обязательно переключись на созданный проект.
2. **APIs & Services → Library** → **Google Calendar API** → **Enable**.

## 4.2. Сервисный аккаунт и ключ

1. **IAM & Admin → Service Accounts → Create service account**.
2. Имя `tg-scheduler-bot` → **Create and continue** → роли пропусти
   (они про доступ к самому проекту, а не к твоему календарю) → **Done**.
3. Открой созданный аккаунт → вкладка **Keys** → **Add key → Create new key**
   → тип **JSON** → **Create**. Файл скачается сам.
4. Скопируй адрес аккаунта — он вида
   `tg-scheduler-bot@имя-проекта.iam.gserviceaccount.com`.

## 4.3. Открыть календарю доступ

Сервисный аккаунт — это отдельный «пользователь», и твоего календаря он пока
не видит. Пусти его:

1. [calendar.google.com](https://calendar.google.com/) → наведи на нужный
   календарь в списке слева → **⋮ → Настройки и общий доступ**.
2. Раздел **Предоставьте доступ отдельным пользователям** → **Добавить
   пользователей** → вставь адрес сервисного аккаунта.
3. Права: **Внесение изменений в мероприятия** → **Отправить**.

> Без этого шага бот получит `404`: календарь для него просто не существует.

## 4.4. Что записать

- `GOOGLE_SERVICE_ACCOUNT_JSON` — **всё содержимое скачанного JSON-файла**,
  целиком, как есть. Открой файл текстовым редактором и скопируй.
- `GOOGLE_CALENDAR_ID` — адрес твоего календаря, обычно это твой gmail.

> `GOOGLE_CALENDAR_ID=primary` здесь **не сработает**: у сервисного аккаунта
> есть собственный пустой `primary`, события ушли бы туда. Бот проверяет это
> при старте и не даст себе запуститься с такой настройкой.

# Шаг 5. Хостинг

Нужен такой, что умеет собирать `Dockerfile` прямо из GitHub-репозитория и
хранить переменные окружения в своей панели. Подойдёт любой из:

| Хостинг | Как |
| --- | --- |
| **Railway** | New Project → Deploy from GitHub repo → выбрать репозиторий |
| **Render** | New → Background Worker → Connect repository |
| **Koyeb** | Create Service → GitHub → Dockerfile |

*Цены и бесплатные лимиты у всех меняются — сверь на сайте перед выбором.*

Важно в настройках:

- **Root Directory** (или Build context): `tg-scheduler-bot` — Dockerfile
  лежит в подкаталоге репозитория, а не в корне.
- **Тип сервиса**: worker / background, **не** web. Бот не слушает порт,
  и проверка доступности HTTP-порта его убьёт.
- **Ветка**: та, где лежит код.

## 5.1. Переменные окружения

В панели хостинга задай:

| Переменная | Значение |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | из шага 1 |
| `ALLOWED_USER_ID` | из шага 1 |
| `OPENAI_API_KEY` | из шага 2 |
| `OPENAI_BASE_URL` | из шага 2 |
| `OPENAI_MODEL` | из шага 2 |
| `OPENAI_TRANSCRIBE_MODEL` | из шага 2 |
| `OPENAI_VISION_MODEL` | из шага 2 (нужна для чтения картинок) |
| `ICLOUD_APPLE_ID` | из шага 3, **необязательно** — см. ниже |
| `ICLOUD_APP_PASSWORD` | из шага 3, **необязательно** — см. ниже |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | весь JSON из шага 4 |
| `GOOGLE_CALENDAR_ID` | твой gmail |
| `TIMEZONE` | `Europe/Moscow` |
| `DAILY_PROMPT_TIME` | `08:45` |

Остальные переменные имеют разумные значения по умолчанию.

> **Про iCloud.** Обе переменные `ICLOUD_*` можно оставить пустыми — тогда
> события пишутся только в Google Calendar. Заполняй их, только если нужна
> отдельная копия в iCloud. Если Google-календарь уже подключён к Маку и
> айфону, приложение «Календарь» покажет обе копии рядом, и каждое событие
> будет выглядеть задвоенным. Половина доступа не годится: либо обе
> переменные, либо ни одной.

> **Если панель искалечила JSON.** Скачанный файл многострочный, и некоторые
> панели принимают только однострочные значения. На этот случай бот понимает
> и base64: закодируй файл и вставь результат в ту же переменную.
>
> ```bash
> base64 -i ~/Downloads/tg-scheduler-bot-XXXX.json | tr -d '\n'   # macOS
> base64 -w0 tg-scheduler-bot-XXXX.json                            # Linux
> ```
>
> Бот сам разберётся, что ему дали — обычный JSON или base64.

# Шаг 6. Проверка

В логах сервиса при старте должно быть:

```
bot: Google: сервисный аккаунт tg-...@....iam.gserviceaccount.com -> календарь ты@gmail.com
bot: Google Calendar: доступ есть
bot: iCloud: доступ есть
bot: Ежедневный вопрос запланирован на 08:45 Europe/Moscow
bot: Поллинг Telegram запущен
```

Если какая-то строка про доступ говорит «доступа нет» — текст ошибки прямо
называет причину; расшифровка в `DEPLOY.md`, приложение B.

Дальше в Telegram:

1. `/start` — бот должен ответить.
2. `/plan`, затем текстом: `завтра в 15:00 созвон с командой на час`.
   Событие должно появиться и в Google Calendar, и в «Календаре» на Mac.
3. Голосовое сообщение — бот покажет распознанный текст и разобранные дела.
4. Файл с расписанием — `.docx`, `.xlsx`, `.csv`, `.txt` или скриншот.
   Бот разберёт его, покажет список найденного и **дождётся подтверждения**:
   файлы разбираются с ошибками чаще коротких сообщений, поэтому в календарь
   ничего не уходит, пока не нажмёшь «Записать».

   Большой файл разбирается частями — до 60 000 символов текста, это
   расписание на учебный год. Шапка таблицы повторяется в каждой части,
   чтобы колонки не теряли смысл, а повторы со стыков отбрасываются.

   Подпись всё равно стоит добавить — «расписание 11Е инж на понедельник».
   Она идёт в разбор вместе с текстом, и чем точнее просьба, тем меньше
   лишнего попадёт в календарь.
5. Ссылка на Google Таблицу — бот откроет её сам:

   ```
   https://docs.google.com/spreadsheets/d/.../edit?gid=123
   добавь отсюда расписание 11Е инж
   ```

   Закрытую таблицу он прочитает от имени сервисного аккаунта, если ей выдан
   доступ на чтение: в таблице **Настройки доступа** -> добавь тот же адрес,
   что и календарю -> права **«Читатель»**. Таблица, открытая по ссылке,
   читается и без этого.

6. Удали тестовые события командой `/today`: она покажет их с номерами,
   а кнопка с номером удалит событие из обоих календарей после подтверждения.

> После удаления бот на тот же текст ответит «уже было»: Google держит
> идентификатор удалённого события занятым. Это не сбой — измени время
> в тексте, и идентификатор пересчитается.

# Шаг 7. Эксплуатация

- **Обновить код**: запушить в ветку — хостинг пересоберёт образ сам.
- **Поменять настройку**: изменить переменную в панели и перезапустить сервис.
- **Логи**: вкладка Logs в панели хостинга.
- **Ротация ключей**: отозвать в исходном сервисе (@BotFather `/revoke`,
  OpenAI → Revoke, appleid.apple.com → Revoke, Google Cloud → удалить ключ
  сервисного аккаунта), затем обновить переменную и перезапустить.

Секреты живут только в панели хостинга. В репозитории их нет и быть не должно:
`.gitignore` и `.dockerignore` исключают `.env`, `token.json`,
`credentials.json` и файлы ключей.
